Agenda multi-hôte Web et MAUI

Prototype

Agenda

Agenda .NET 10 partagé entre Web Blazor et MAUI, avec calendrier, événements, API REST et persistance SQLite.

Objectif
Partager interface et cas d’usage entre plusieurs hôtes .NET.
Démonstration
Blazor, MAUI, API REST, EF Core/SQLite, architecture multi-hôte, tests et CI.
Domaines
Web Mobile Backend Architecture Accessibilité
Dépôt GitHub ↗ Télécharger le CV

Problème

Ce que le projet cherche à résoudre

Réutiliser les mêmes composants Razor et cas d’usage dans le Web et MAUI sans confondre interface, domaine et persistance.

Rôle

Mon rôle

Conception et développement d’un agenda .NET 10 multi-hôte : domaine, cas d’usage, persistance EF Core/SQLite, interface Razor partagée, Web Blazor, API et MAUI Blazor Hybrid.

Stack

C# .NET 10 ASP.NET Core Blazor .NET MAUI Entity Framework Core SQLite REST xUnit Tests GitHub Actions

Architecture

Comment le système est structuré

  • Domain porte événements et invariants.
  • Application orchestre les cas d’usage.
  • UI Razor est partagée entre Web et MAUI ; API expose les mêmes cas d’usage.

Décisions

Décisions techniques

  • Partager l’interface. Les composants Razor restent dans un projet commun à Web et MAUI.
  • Garder une persistance locale MAUI. L’hôte mobile conserve sa base privée tant qu’aucun protocole de synchronisation n’est implémenté.

Schéma

Vue d’ensemble de l’architecture

Le schéma complète l’étude de cas avec les composants et frontières réellement présents dans le projet.

Implémentation

Points techniques principaux

  • Calendrier mensuel avec navigation et sélection de journée.
  • Création, modification et suppression d’événements.
  • Composants Razor partagés entre Blazor Interactive Server et MAUI Blazor Hybrid.
  • API REST Minimal APIs/OpenAPI.
  • Persistance EF Core/SQLite et tests séparés par couche.

Difficultés

Difficultés résolues

  • Partager une UI entre deux hôtes. Les composants doivent fonctionner dans Blazor Server et MAUI Blazor Hybrid.

Qualité

Tests et garde-fous

  • Nullable et avertissements traités comme erreurs.
  • Tests domaine, application, infrastructure et UI.

Livraison

Livraison et CI/CD

  • GitHub Actions exécute la validation .NET 10.

Résultats

Résultats observables

  • CRUD d’événements, calendrier, API REST et hôte MAUI intégrés.

Compromis

Compromis techniques

  • Le partage Razor réduit la duplication mais impose une UI compatible avec les deux hôtes.

Limites

Limites assumées

  • Pas de synchronisation MAUI ↔ API.
  • Pas de notifications natives.
  • Pas d’authentification multi-compte.

Suite

Prochaines étapes

  • Définir un protocole de synchronisation avant de relier les bases locales à l’API.

Captures

Le produit en situation

Preuve de compétence

Ce que ce projet démontre

  • Les mêmes composants Razor sont réutilisés dans plusieurs hôtes.
  • Domaine, contrats, application et infrastructure sont séparés.
  • La synchronisation MAUI ↔ API n’est pas présentée comme existante.

Gestionnaire de tâches et Kanban avancé

En cours

Kanban

Gestionnaire .NET 10 avec vues Liste/Kanban, règles WIP, récurrence, API REST et persistance SQLite.

Objectif
Modéliser les règles métier d’un gestionnaire de tâches au-delà d’un simple CRUD.
Démonstration
Règles WIP, Blazor, API REST, EF Core/SQLite, tests et CI.
Domaines
Web Backend Full-stack Architecture Accessibilité
Dépôt GitHub ↗ Télécharger le CV

Problème

Ce que le projet cherche à résoudre

Partager les mêmes règles métier entre l’interface Blazor et l’API tout en conservant l’ordre, les limites WIP et l’historique.

Rôle

Mon rôle

Conception et développement d’un gestionnaire de tâches C#/.NET 10 avec domaine métier, persistance EF Core/SQLite, interface Blazor et API REST.

Stack

C# .NET 10 ASP.NET Core Blazor Entity Framework Core SQLite REST xUnit Tests GitHub Actions

Architecture

Comment le système est structuré

  • Domain porte les invariants des tâches et colonnes.
  • Application orchestre les cas d’usage partagés.
  • Infrastructure fournit EF Core/SQLite ; Web et API sont deux points d’entrée.

Décisions

Décisions techniques

  • Partager les cas d’usage. Web et API passent par la même couche Application.
  • Faire des limites WIP une règle métier. Les déplacements sont refusés par le domaine lorsque la capacité est atteinte.

Schéma

Vue d’ensemble de l’architecture

Le schéma complète l’étude de cas avec les composants et frontières réellement présents dans le projet.

Implémentation

Points techniques principaux

  • Tâches, sous-tâches, étiquettes, priorités, échéances, rappels et récurrence.
  • Vues Liste et Kanban avec réorganisation persistante et alternative clavier.
  • Colonnes configurables et limites WIP.
  • Import/export JSON/CSV et API REST.
  • EF Core/SQLite, tests multi-couches et CI GitHub Actions.

Difficultés

Difficultés résolues

  • Maintenir la cohérence du Kanban. Ordre, colonne et règles WIP doivent rester cohérents pour souris, clavier et API.

Qualité

Tests et garde-fous

  • Tests domaine, application et infrastructure.
  • Formatage et audit NuGet en CI.

Livraison

Livraison et CI/CD

  • GitHub Actions exécute build, tests, formatage et audit.

Résultats

Résultats observables

  • Gestionnaire fonctionnel avec vues Liste/Kanban et règles WIP.

Compromis

Compromis techniques

  • SQLite convient au périmètre local mais ne vise pas la collaboration distribuée.

Limites

Limites assumées

  • Pas d’authentification ni de collaboration multi-utilisateur.

Suite

Prochaines étapes

  • Harmoniser le branding interne Todo/Kanban avant une release stable.

Captures

Le produit en situation

Des états complémentaires sélectionnés pour montrer l’interface et les parcours réellement implémentés.

Preuve de compétence

Ce que ce projet démontre

  • Les limites WIP sont portées par le domaine.
  • Web et API réutilisent la couche Application.
  • Les interactions Kanban restent accessibles au clavier.

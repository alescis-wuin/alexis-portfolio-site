# P2.4-E — preuves visuelles et médias typés

Statut : implémenté sur `feature/p2.4-projects-redesign` après P2.4.3.

## Objectif

P2.4-E rend les preuves visuelles explicites et vérifiables avant l'ajout du viewer interactif P2.4-F. Le lot privilégie les captures réelles du produit, conserve les diagrammes techniques sourcés et fait de la validité des fichiers média un invariant du dépôt.

## Décision de schéma

`data/projects.json` utilise `schemaVersion: 5`.

Chaque entrée média porte désormais un champ `kind` :

- `screenshot` : capture réelle du produit, stockée en WebP ;
- `diagram` : représentation technique sourcée, stockée en SVG.

Le hero d'un projet public doit être un `screenshot`. L'architecture doit être un `diagram`. La galerie accepte les deux types afin que P2.4-F puisse adapter son comportement sans déduire le rôle d'un média depuis son nom de fichier.

Le générateur expose le type via `data-media-kind` sur les surfaces générées.

## Actualisation Alycia

Les anciens WebP d'Alycia étaient des illustrations schématiques et leurs conteneurs RIFF étaient incomplets pour plusieurs décodeurs standards. P2.4-E les remplace par des captures réelles du produit :

- `hero.webp` : espace Conversations avec historique, reasoning séparé et composer ;
- `configuration.webp` : espace Models et paramètres de génération ;
- `provider.webp` : espace Provider/Runtime et cycle de vie llama.cpp CUDA.

Le diagramme `architecture.svg` est conservé : ses frontières Desktop / Presentation / Application / Domain / Infrastructure et l'adaptateur llama.cpp restent cohérents avec l'architecture publique actuelle. Aucun diagramme décoratif ou capacité non implémentée n'est ajouté.

## Validation média

`npm run validate:media` vérifie tous les médias déclarés :

- présence du fichier ;
- signature WebP RIFF/WEBP ;
- cohérence entre la longueur RIFF déclarée et la taille réelle ;
- intégrité des chunks nécessaires aux dimensions ;
- dimensions WebP réelles identiques à `width` / `height` ;
- racine et dimensions numériques des SVG ;
- absence de `<script>` dans les SVG.

La commande fait partie de `check:basic` et `check:strict`.

## QA visuelle

La matrice de capture ajoute une scène `*-gallery` en Full HD pour chacun des six projets publics. Le plan passe de 45 à 51 captures et couvre désormais les médias de galerie, auparavant validés fonctionnellement mais pas capturés comme scène dédiée.

## Hors périmètre

P2.4-E ne modifie pas l'interaction des médias. Restent différés :

- P2.4-F : viewer d'image natif basé sur `<dialog>` ;
- P2.4-G : fermeture responsive, accessibilité et performance finale.

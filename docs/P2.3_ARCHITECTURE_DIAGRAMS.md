# P2.3-C — diagrammes d’architecture sourcés

## Objectif

Cette sous-phase ajoute un diagramme SVG homogène pour chacun des cinq projets retenus
pour la présentation visuelle. Les schémas décrivent uniquement des composants présents
ou explicitement documentés dans les révisions auditées.

Ils ne sont pas encore branchés dans `data/projects.json` : P2.3-D introduira le contrat
`visuals`, les intégrera aux pages et publiera Agenda/Kanban si les invariants éditoriaux
sont satisfaits.

## Streamfolio

Le diagramme représente le navigateur/PWA, Spring Boot, PostgreSQL/Flyway pour les données
métier, Redis pour les sessions runtime, MinIO pour les médias, les jobs média persistés
et FFmpeg local.

## Kanban / Todo

Le schéma reprend `Todo.Web`, `Todo.Api`, `Todo.Ui`, `Todo.Application`, `Todo.Domain`,
`Todo.Contracts`, `Todo.Infrastructure` et SQLite. Le contrôle WIP reste présenté comme
une règle du domaine.

## Agenda

Le diagramme met en évidence Web, MAUI et API, l’UI Razor partagée, Application, Domain,
Contracts et Infrastructure. L’hôte MAUI utilise sa base privée locale ; aucune
synchronisation MAUI ↔ API n’est représentée puisqu’elle n’est pas implémentée.

## Calcufolio

Le diagramme suit le câblage réel : Avalonia et ses adaptateurs d’entrée, contrôleurs et
services applicatifs, `ExpressionEvaluationService`, `ExpressionEngine`, puis
`ExpressionTokenizer` → `ExpressionParser` → `ExpressionEvaluator` → `CalculationEngine`.

`Calcufolio.Infrastructure` est uniquement indiqué en pointillés comme projet sans
implémentation runtime auditée ; aucune persistance n’est inventée.

## Aelia

Le diagramme illustre la dépendance de la JavaFX UI à `WeatherDashboardProvider`, son
implémentation par `SimulatedWeatherDashboardProvider`, le modèle météo typé et les
formatters UI. L’adaptateur distant reste explicitement futur/non implémenté.

## Règles graphiques

- SVG autonomes 1600×900 avec `viewBox` ;
- `<title>` et `<desc>` dans chaque fichier ;
- aucun script ni ressource externe ;
- composants implémentés en traits pleins ;
- éléments futurs/non actifs en traits pointillés ;
- terminologie alignée sur les projets sources ;
- diagrammes conçus pour rester lisibles dans un `<img>` responsive.

## P2.3-D

La sous-phase suivante devra introduire `visuals.hero`, `visuals.architecture` et
`visuals.gallery`, ajouter les études de cas sourcées d’Agenda et Kanban, publier ces
deux projets selon la hiérarchie retenue, générer les médias dans les pages et ajouter
les validations/tests correspondants.

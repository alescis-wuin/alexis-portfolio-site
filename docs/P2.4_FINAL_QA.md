# P2.4-G - cloture responsive, accessibilite et performance

Statut : implemente sur `feature/p2.4-projects-redesign` apres P2.4-F.

## Objectif

P2.4-G ferme le redesign P2.4 sans ajouter de fonctionnalite produit. Le lot transforme les criteres de fin de phase en garde-fous reproductibles : reflow, matrice responsive, accessibilite structurelle, viewer aux extremes de viewport, dependances runtime locales et budgets de poids statiques.

## Matrice responsive finale

Les E2E parcourent la page d'accueil, le catalogue et les six etudes de cas sur :

- 320x720 (reflow) ;
- 390x844 ;
- 768x1024 ;
- 1024x768 ;
- 1366x768 ;
- 1920x800 ;
- 1920x1080 ;
- 2560x1080 ;
- 3440x1440 ;
- 3840x2160.

Chaque surface doit rester sans overflow horizontal, conserver exactement un `main` et un `h1`, declarer `alt` sur chaque image et ne pas exposer de bouton sans nom accessible de base.

Le viewer Alycia est en plus ouvert et mesure sur les deux extremes 320x720 et 3840x2160. Le panneau et l'image doivent rester contenus dans le viewport, `Escape` ferme le dialogue et le focus revient au declencheur.

## Accessibilite de cloture

P2.4-G ne remplace pas les contrats deja couverts par P2.3.5, P2.3.6 et P2.4-F. Il les consolide avec une verification transversale de toutes les surfaces publiques :

- reflow a 320 px ;
- absence d'overflow horizontal ;
- structure `main` / `h1` unique ;
- attribut `alt` present sur les images ;
- boutons nommes ;
- comportement modal natif et restitution du focus aux extremes de viewport ;
- `prefers-reduced-motion` conserve par les garde-fous existants.

`html-validate`, les tests de focus/contraste existants et les E2E du viewer restent les sources de verite pour leurs contrats respectifs.

## Budgets performance statiques

`scripts/validate-project-performance.mjs` ajoute des budgets deterministes, independants du materiel et du reseau :

| Surface | Budget |
| --- | ---: |
| CSS critique cumule | <= 112 KiB |
| `assets/js/main.js` | <= 20 KiB |
| accueil HTML | <= 48 KiB |
| catalogue HTML | <= 40 KiB |
| une page projet HTML | <= 32 KiB |
| hero screenshot | <= 128 KiB |
| screenshot de galerie | <= 160 KiB |
| diagramme SVG | <= 20 KiB |

Baseline au moment de P2.4-G :

- CSS critique : 78.3 KiB ;
- JS principal : 11.5 KiB ;
- accueil : 33.9 KiB ;
- catalogue : 24.6 KiB ;
- plus grande page projet : 19.2 KiB (`streamfolio`) ;
- plus grand hero : 92.9 KiB (`aelia`) ;
- plus grand screenshot de galerie : 116.3 KiB (`aelia/map.webp`) ;
- plus grand diagramme : 7.5 KiB (`agenda/architecture.svg`).

Le validateur refuse aussi les scripts, stylesheets, preloads ou imports CSS runtime provenant d'une origine HTTP externe. Le portfolio garde ainsi son contrat sans dependance runtime tierce.

La commande `npm run validate:performance` fait partie de `check:basic` et `check:strict`.

## QA visuelle finale

La matrice visuelle ajoute `320x720` et `3840x2160` aux scenes structurantes de l'accueil, du catalogue et du viewer. Le plan passe de 53 a 61 captures reproductibles. Les six projets conservent leurs scenes hero, architecture et galerie deja etablies.

## Critere de sortie P2.4

P2.4 est considere ferme quand les controles suivants sont tous verts sur le meme working tree :

1. `npm run check:strict` ;
2. `npm run capture:visual` avec 61/61 captures ;
3. `git diff --check` ;
4. revue du perimetre Git avant commit.

P2.4-G ne modifie ni le schema media v5, ni les contenus editoriaux, ni les interactions introduites par P2.4-F. Toute evolution fonctionnelle ulterieure doit appartenir a une phase distincte.

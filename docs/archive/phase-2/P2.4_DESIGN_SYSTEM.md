# P2.4-B - Design system and base project identity

Status: implementation contract.

## Scope

This phase establishes the visual substrate defined by P2.4-A without doing the later layout
rewrite.

Included:

- semantic foundation tokens for future frame/content/reading widths;
- five project identities driven by `data-project-slug`;
- per-project colors plus non-color motifs;
- stronger, media-first project cards;
- branded detail-page masthead and media framing;
- generated detail pages expose their slug on `<body>`;
- generator and E2E regression coverage.

Deferred:

- P2.4-C: wide/ultrawide layout and 12/16-column restructuring;
- P2.4-D: editorial restructuring of project case-study sections;
- P2.4-E: new screenshots, diagrams and typed-media schema decision;
- P2.4-F: native `<dialog>` image viewer;
- P2.4-G: final responsive/accessibility/performance QA.

No `data/projects.json` schema change is allowed in this phase.

## Foundation tokens

- `--frame-max: 175rem`
- `--content-max: 112rem`
- `--reading-max: 72ch`
- `--wide-reading-max: 86ch`
- `--gutter: clamp(1rem, 2.6vw, 4rem)`
- `--section-space: clamp(4.5rem, 8vw, 9rem)`
- project tokens:
  - `--project-accent`
  - `--project-accent-2`
  - `--project-glow`
  - `--project-pattern-image`
  - `--project-pattern-size`

The frame/content tokens are introduced now but the existing layout is not migrated to them until
P2.4-C.

## Accessibility rules

- all content text keeps the existing semantic text colors;
- project colors are used mainly for borders, rails, glows and low-opacity surfaces;
- no state is identified by color alone;
- motion is disabled for the new card transforms under `prefers-reduced-motion: reduce`;
- generated DOM order is unchanged;
- no new dependency or JavaScript interaction is introduced.

## Detail-page contract

Each public generated page has:

```html
<body data-project-slug="streamfolio">
```

The generator owns this attribute. It must never be manually edited in generated HTML.

## Card contract

Existing `data-project-slug` on project cards remains the source of identity. CSS maps each slug to
its tokens, so design data is not duplicated inside `data/projects.json`.

## Validation

- schema remains v4;
- Solvia remains unpublished and has no generated public page;
- all five public detail pages expose the correct body slug;
- project-card CSS defines the P2.4-B media-first identity layer;
- the full strict test suite remains green.

## P2.4-C — géométrie large et ultrawide

P2.4-C rend effectives les trois échelles définies en P2.4-B :

- `frame` : composition, grilles et médias jusqu’à `--frame-max` ;
- `content-shell` : structure courante jusqu’à `--content-max` ;
- `reading` : prose bornée par `--reading-max`.

`.container` reste un alias de compatibilité de `content-shell` pour le markup historique. Les nouveaux wrappers générés utilisent explicitement `frame` ou `content-shell`.

La homepage passe à une composition 12 colonnes à partir de 1440 px puis 16 colonnes à partir de 1920 px. Les quatre projets featured restent en 2×2 sur desktop standard et passent à quatre colonnes lorsque la largeur disponible le permet.

Le catalogue utilise 1, 2, 3, 4 puis 5 colonnes selon la largeur. Les pages projet donnent la frame large au masthead, au diagramme d’architecture et à la galerie, tout en maintenant les blocs textuels dans le content shell.

La matrice Playwright couvre 390×844, 768×1024, 1024×768, 1280×800, 1440×900, 1920×1080, 2560×1080, 3440×1440 et 3840×2160 avec des assertions relationnelles sur l’overflow, les largeurs, les colonnes, le rail et les médias lazy-loadés.

## P2.4-D — profondeur éditoriale et identité des projets

P2.4-D sépare explicitement l’identité visuelle d’un projet de la lisibilité de son contenu.

Sur les cartes, les motifs géométriques de P2.4-B ne sont plus peints derrière le texte : l’identité repose désormais sur l’accent propre au projet, la barre supérieure, le cadre média, les badges, les faits et les actions. Le halo décoratif circulaire situé derrière l’action GitHub est supprimé. Le lien vers le dépôt devient une action compacte de 44 px minimum, centrée, identifiable et utilisable au clavier.

Les miniatures de cartes utilisent systématiquement `visuals.hero` afin de montrer le produit réel plutôt qu’une illustration d’architecture ou de concept. Elles sont placées dans un cadre 16:9 avec `object-fit: contain`, ce qui interdit le rognage des captures de formats différents (notamment Kanban et Calcufolio).

Les motifs restent disponibles sur les pages détail, où ils ont davantage d’espace pour participer à l’identité. Ils sont confinés à la partie visuelle du masthead sur grand écran et fortement atténués sur mobile. Streamfolio adopte des courbes et points inspirés du média, Agenda un rythme ponctuel de calendrier, tandis que Kanban et Calcufolio conservent leurs motifs structurants.

Le masthead projet gagne aussi une hiérarchie éditoriale plus directe : sous le titre et le résumé, un bloc `Objectif / Démonstration` expose immédiatement la mission et la preuve attendue, puis viennent les catégories et les actions. Cette synthèse réutilise les données canoniques existantes ; aucun second contenu éditorial n’est dupliqué dans les templates.

Les garde-fous P2.4-D vérifient notamment que les cartes utilisent le hero réel, que le média est rendu sans rognage, que les anciens pseudo-éléments décoratifs des cartes sont absents, que les CTA GitHub conservent une cible d’au moins 44 px et que les pages détail exposent la synthèse éditoriale issue des données canoniques.

### P2.4-D — passe de densité et lisibilité

La seconde passe P2.4-D traite la densité observée en 16:9 et sur écrans très larges : le masthead d’une étude de cas doit rester lisible sans transformer le premier écran en affiche surdimensionnée. Les pages projet utilisent donc une échelle typographique spécifique, un espacement vertical plus compact et un média hero borné par la hauteur du viewport. Sur mobile, ces contraintes de hauteur sont relâchées afin de conserver un flux naturel.

Les métadonnées ne doivent plus être confondues avec des actions. Les tags adoptent une forme d’étiquette compacte, à angles modérément arrondis et rail coloré, tandis que les vrais boutons conservent une cible tactile d’au moins 44 px et une silhouette en pilule. Les cartes exposent en plus un libellé `Technologies` et le masthead un libellé `Domaines`.

Sur les pages projet, `Retour aux autres projets` devient une action permanente dans l’en-tête sticky, à fond transparent ; le breadcrumb redondant du masthead est supprimé. Le résumé visible du masthead utilise `summary`, plus court et éditorial, tandis que `metaDescription` reste réservé aux métadonnées de page.

Les commandes haut/bas de la homepage deviennent plus petites, transparentes et sans ombre portée afin de ne plus masquer le contenu. Les diagrammes d’architecture sont plafonnés en hauteur et centrés plutôt qu’agrandis jusqu’à remplir les écrans ultrawide. Les cinq SVG utilisent des pointes de flèche en unités absolues, des libellés plus petits et des traits allégés ; Agenda et Kanban emploient des liaisons orthogonales pour éviter les croisements au-dessus des composants.

## P2.4-D QA — captures visuelles reproductibles

La validation éditoriale est complétée par un plan de capture versionné dans `tests/visual/visual-cases.mjs`. Les mêmes scènes sont capturées avec Chromium, des viewports fixes, un seul worker, un thème et des préférences de mouvement déterministes. Les captures ne sont pas commitées : elles sont conservées sous `artifacts/visual/`, accompagnées d'un manifeste, des SHA-256 et du rapport Playwright, puis publiées comme artifacts des PR GitHub Actions. Les assertions E2E restent la source de vérité pour les contraintes fonctionnelles et géométriques ; les captures servent à la revue visuelle répétable.
